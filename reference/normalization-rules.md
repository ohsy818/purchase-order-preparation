# 조건 정규화 규칙

`scripts/normalize_terms.py`가 구현하는 규칙이다.
**이 스크립트의 목적은 결측·모순을 찾아내는 것이지, 값을 지어내는 것이 아니다.**

## 1. 리드타임

```
단일값  "3일"        → 3, 원문 보존
범위    "5~7일"      → lead_time_basis 에 따라
                        max → 7 / min → 5 / mid → 6
                      원문 "5~7일" 을 함께 보존
없음                 → None, 「리드타임 확인 필요」
"즉시","재고보유"     → None, 「리드타임 확인 필요」
```

**원문을 반드시 남긴다.** 7일로 계산했더라도 "5~7일"이었다는 사실이 보여야
납기가 어긋났을 때 원인을 안다.

## 2. MOQ·포장 단위

```
MOQ 없음        → None, 「MOQ 확인 필요」.  1로 가정하지 않는다
포장 단위 없음   → None. required_terms 에 있으면 조건 미비
MOQ < 포장 단위 → 모순. 「조건 모순」 표시
```

MOQ 10, 포장 단위 12인 경우처럼 서로 안 맞는 값은 그대로 두고 표시한다.
스크립트가 임의로 조정하지 않는다.

## 3. 단가

```
기준 단위 없음        → 「단가 기준 단위 확인 필요」
기준 단위 ≠ 재고 단위 → 환산하지 않고 「단위 불일치」 표시
부가세 표기 없음
  tax_convention = unspecified → 「부가세 확인 필요」
  tax_convention = included/excluded → 그 값으로 간주하고 근거를 표시
수량 구간별 단가      → 구간 전체를 보존. 한 구간을 고르지 않는다
문서 단가 ≠ 마스터 단가 → 둘 다 표기하고 「단가 불일치」 표시
```

**단가 환산을 하지 않는 이유** — BOX당 단가를 EA로 나누려면 입수를 알아야 하는데,
입수가 확실하지 않으면 단가가 통째로 틀린다. 확실할 때만 사람이 한다.

## 4. 통화

```
base_currency 와 다른 통화 → 원 통화로 표기, 「통화 상이」 표시
환산                        → 하지 않는다
```

환율은 시점에 따라 달라진다. 비교표에 환산값을 넣으면
언제 기준인지 모르는 숫자가 남는다.

## 5. 판정 유형 결정

```
1) 마스터에 없고 초안만 생성됨            → draft_only
2) 공급 조건이 하나도 없음                → no_supplier
3) required_terms 중 결측이 있음          → terms_incomplete
4) 그 외                                   → sourceable
```

순서대로 먼저 맞는 것을 적용한다.

## 6. 표시 부여

| 표시 | 조건 |
|---|---|
| `long_lead` | 리드타임 ≥ `long_lead_days` |
| `multi_source` | 그 품목의 공급 옵션이 2개 이상 |
| `single_source` | 1개 |
| `terms_missing` | `required_terms` 중 결측 |
| `price_mismatch` | 문서 단가 ≠ 마스터 단가 |
| `unit_mismatch` | 단가 기준 단위 ≠ 재고 단위 |
| `currency_diff` | `base_currency`와 다름 |
| `tax_unknown` | 부가세 처리 불명 |
| `terms_conflict` | MOQ < 포장 단위 등 |

## 7. 주문 마감일 역산

`long_lead` 품목에 필요 시점이 주어졌을 때만.

```
주문 마감일 = 필요 시점 − 리드타임 − safety_buffer_days
```

마감일이 이미 지났으면 「마감 경과」로 표시한다. 이미 늦었다는 뜻이다.

## 검산

| 항목 | 성립해야 하는 식 |
|---|---|
| 분류 총합 | 네 유형의 합 = 입력 품목 수 |
| 중복 없음 | 한 품목이 두 유형에 들어가지 않음 |
| sourceable 조건 | `required_terms`가 모두 채워져 있음 |
| 옵션 보존 | 입력 공급 옵션 수 = 출력 옵션 수 (버리지 않는다) |
| 순위 없음 | 출력에 우열·추천 필드가 없음 |
| 플래그 일치 | `all_items_sourceable` == (`blocked_items` 0건) |

「순위 없음」 검산이 있는 이유 — 이 스킬이 공급처를 고르기 시작하면
사람이 검토를 건너뛴다. 구조적으로 막는다.
