# 문서에서 속성 추출

견적서·카탈로그·사양서는 거래처마다 양식이 다르다.
표 구조를 맞추려 하지 말고 **항목 단위로** 뽑는다.

## 추출 항목

| 항목 | 필수 | 주의 |
|---|---|---|
| 품목명 | ● | **규격을 품목명에 섞지 않는다.** 검색이 어려워진다 |
| 규격 | ● | 용량·치수·순도·등급·재질 |
| 단위 | ● | EA / BOX / SET / L. **포장 입수를 함께** (BOX 10입) |
| 카테고리 | ○ | `category_scheme`에 있는 값만. 없으면 비워 둔다 |
| 공급처 | ● | |
| 공급처 품번 | ○ | 있으면 반드시 남긴다. 재주문·문의에 쓴다 |
| 단가 | ● | **부가세 포함 여부를 명시** |
| 통화 | ○ | 원화가 아니면 반드시 |
| 리드타임 | ● | 일 단위. 범위면 범위 그대로 |
| MOQ | ● | 없으면 「확인 필요」. **1로 가정하지 않는다** |
| 유효기간 | ○ | 견적 유효기간. 지났으면 표시 |

## 확신도가 낮을 때

**값을 비워 두고 「확인 필요」로 표시한다.**

| 상황 | 잘못된 처리 | 올바른 처리 |
|---|---|---|
| 단가에 부가세 표기가 없다 | 별도로 가정 | 「부가세 확인 필요」 |
| "즉시 출고"라고만 적혀 있다 | 리드타임 0 | 「리드타임 확인 필요」 |
| MOQ 칸이 비었다 | 1로 채움 | 「MOQ 확인 필요」 |
| 규격이 이미지로만 있다 | 추측해서 입력 | 「규격 확인 필요」 |
| 단위가 "개"인지 "박스"인지 모호 | 개로 가정 | 「단위 확인 필요」 |

추측해서 채운 값은 마스터에 남아 이후 모든 주문을 오염시킨다.
비어 있는 값은 사람이 채우지만, **틀린 값은 아무도 고치지 않는다.**

## 자주 틀리는 것

**단가 단위 불일치**
견적서에 "BOX당 50,000원"인데 마스터 단위가 EA면, 단가를 그대로 넣으면 10배 틀린다.
단가와 함께 **그 단가의 기준 단위**를 반드시 뽑는다.

**수량 구간별 단가**
"1~9개 5,000원 / 10개 이상 4,500원" 같은 경우.
구간을 그대로 남긴다. 임의로 한 구간을 고르지 않는다.
주문수량이 정해지는 건 다음 단계다.

**할인 전/후 가격**
정가와 할인가가 함께 있으면 **둘 다** 남기고 어느 쪽이 적용 조건인지 적는다.

**세트 구성품**
"세트 구매 시" 가격이면 세트 조건을 명시한다.
단품으로 사면 그 가격이 아니다.

**부대비용**
배송비·설치비·검교정비가 별도인지 포함인지.
별도면 그 사실을 조건에 남긴다. 금액 비교가 뒤집힐 수 있다.

## 초안 등록

`auto_create_draft = true`이면 초안을 만들고, 아니면 목록만 낸다.
어느 쪽이든 **비워 둔 항목을 반드시 함께 보고한다.**

```markdown
| 품목명 | 규격 | 단위 | 카테고리 | 공급처 | 단가 | 리드타임 | 비워 둔 항목 |
|---|---|---|---|---|---|---|---|
| 육각볼트 | M6×20 SUS304 | EA | (미지정) | (주)대한 | 350 | 3일 | 카테고리, MOQ |
```

**등록은 초안 상태까지만.** 확정은 사람이 한다.
